# Follow-up primary-source checks

Accessed October 10, 2026. This note supplements the immutable foundation source ledger. It covers the narrow follow-up questions below, not an exhaustive survey of recent papers. No upstream implementation, task dataset or evaluation asset was copied during these checks.

## Post-training infrastructure

[Proximal, Post-training infrastructure at Proximal](https://www.proximal.so/blog/posttraining-infra/), published October 8, 2026. The article separates inference/training capacity from isolated tool execution. It records sampled token IDs and log-probabilities beside inference, keeps one adapter version throughout a rollout, excludes excessively stale groups, and persists checkpoints plus unused completed rollouts. Its latency, throughput and DeepSWE gains are internal reported measurements, not reproduced World Engine results.

Design implication: exact application request bytes and action text remain insufficient for on-policy training. World Engine's native/recorded-JSON evidence stays excluded from training exports. Its local semaphore and Docker timings do not implement or validate a GPU-serving scheduler, distributed checkpoint recovery or policy-version synchronization.

## Mixed inference scheduling

[Hong et al., Scheduling Mixed RL Rollouts Beyond Prefix Locality](https://arxiv.org/abs/2608.11152v1), version 1 submitted August 11, 2026. MISA-T considers session admission, KV-capacity allocation and residence time for mixed RL workloads. The paper reports comparisons against a cache-aware router while preserving the trainer's requested workload mixture. Those experiments are not reproduced here.

Design implication: faster average serving can change which tasks finish and enter training. Any future scheduler needs mixture and staleness accounting, not just maximum concurrent requests. Current single-machine evaluation instead fixes task order and retains failures and stopped slots; it does not claim MISA-T compatibility or comparable throughput.

## Public task grading and rights

[Proximal-Labs, frontier-swe-v2](https://github.com/Proximal-Labs/frontier-swe-v2), current repository README inspected October 10. It describes 34 long-horizon tasks, automated verification, pinned environments and Harbor-compatible task layout. Its evaluation-purpose notice and task-specific upstream attribution are not blanket permission to train on or redistribute every task asset. No task was imported into World Engine from this repository.

[FrontierSWE V2 methodology](https://www.frontierswe.com/blog/v2), official benchmark article inspected October 10. It describes attempts to exploit public evaluation inputs or rewritten checks and a collection-time daemon-permission incident. The benchmark's clean verifier invalidated some apparent successes; the reported daemon fix is scoped to that incident, not a universal claim about present Modal security.

Design implication: mutable agent tests are not grading authority. Controller/grader files, secrets and daemon sockets must remain inaccessible to the agent. A container constraint or replay checksum does not authenticate a malicious host. World Engine's approved local Docker images, isolated collector and independent trusted grading test a narrower boundary.

A bounded metadata-only check on October 10, 2026 read the already-installed public `qwen3:8b` through loopback `/api/show`, without chat or downloads. Its reported template hash was `ae370d884f108d16e7cc8fd5259ebc5773a0afa6e078b11f4ed7e39a27e0dfc4`. The template visibly serializes each `.Function` from `.Tools` inside Hermes-style tags. Actual v2 seed-zero wire retains `list_requests.start_index` minimum/default one, yet its first three calls use zero and are rejected. V2 omits duplicated schemas from user content, not from the native tools array. Template constraint omission is therefore unsupported; schema salience/placement is an unisolated hypothesis. This metadata inspection is not an attestation of rendered tokens, context truncation or cache hits.

[Qwen's official function-calling guide](https://qwen.readthedocs.io/en/stable/framework/function_call.html), accessed October 10, 2026, recommends Hermes-style tools, describes JSON Schema parameters and retains application-side handling for malformed calls. That documentation supports the format comparison, not a diagnosis of these particular failures.
