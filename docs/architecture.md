# Architecture and Trust Boundaries

World Engine is a local single-operator rollout service. It replaces none of the archived prototype files in `prototypes/failure-to-intervention`; that experiment remains a reference for invoice preservation and deterministic verification.

## Ownership

`Environment` owns seeded state, validated tool transitions, atomic rollback on denial, detached observations/snapshots, and trusted final-state grading. `Provider` sees only the current model-visible observation and previous actions/results. `rollout` pins environment, grader, prompt, policy-source and task fingerprints, applies bounded decisions, and records every accepted or rejected transition. `Store` owns SQLite WAL persistence, append-only episode/event records, content hashes and efficient summary queries. `RunManager` owns admission, global concurrency, process ownership, cancellation and shutdown. FastAPI and the CLI use that same manager.

The four reference worlds are `crm-merge` (1.1.1), `refund-ops` (1.1.2), `incident-control` (1.0.1), and `access-provisioning` (1.0.0). Permission rules belong to tool services: agents cannot write approval results, ledger records, incident health, grader labels, or arbitrary state. Each world protects unrelated records and resource conservation. CRM/refund graders independently fold exact initial-derived change certificates and compare the whole operational state. Incident grading checks initial identities and authorized check/review/execution history. These contracts do not call the transition implementation or a reference policy to grade.

The three legacy worlds retain shaped diagnostic credit for safe, normally finished incomplete work. Access uses binary outcome reward: one only for safe settlement plus explicit finish, otherwise zero. Preservation or inspection alone is not task progress. Timeouts, cancellation, provider errors and step exhaustion receive zero episode reward. Passing requires every trusted check, a normal completed episode, and an explicit finish. A batch can be completed while its episodes fail the task; `termination=max_steps` remains a failed task outcome. Neither legacy partial credit nor passing scripted controls establishes a calibrated training objective.

## Determinism and Evidence

Reset uses an isolated `random.Random(seed)`, integer cents, deterministic dates, and service-owned logical audit sequences. Snapshot hashes include the seed, world version, step tick, finished state and all operational state, including rejected-action ticks. Initial data used by graders is deep-copied and never returned to providers as grader state. The three legacy observations expose operational records and public task policy, not expected final values or check results. Access instead exposes a bounded queue and current tool result. Paged exact staff/email searches, employee/manager reads and policy discovery reveal only requested records. Its private directory, catalog and review history remain outside initial policy observation. Full snapshots are trusted operator evidence, not provider inputs.

Every episode records the collection Git HEAD and dirty flag when running from a Git checkout, environment/grader module SHA256 fingerprints, task/tool-schema hash, initial prompt/state hashes, Python version, provider class/source fingerprint, model identifier, and local catalog model digest when available. Source fingerprints include a custom world's complete Python module and class, so changes to helper definitions in the custom world module invalidate replay; external dependency revisions still need pinned package/source manifests. `policy_hash` is a configuration/source fingerprint and includes the local model digest; it is not an attestation of a remote model's weights. Hosted model aliases cannot provide reproducible weight identity. Replay requires matching environment/grader implementation fingerprints and verifies every action, result, observation, state hash and final trusted grade. It also recomputes initial/final snapshots, task/prompt/scenario/lineage hashes, split assignment, step/invalid-action counts and controller policy contexts, then checks termination against world completion and reward/pass labels against trusted grading. Truncated, aborted or not-normally-finished episodes have zero episode reward, regardless of partial grader credit. A normally finished legacy episode can retain shaped reward while failing its business task. Replay proves internal consistency and state transitions for recorded actions; it does not authenticate collection provenance, verify reported timing/token usage or external failure causes, or regenerate stochastic model output. For custom providers, recorded `policy_input` is the controller context, not a claim about arbitrary provider-internal request formatting. Storage append/hash checks alone are not semantic validation; every training export applies replay before admitting an episode. Code changes intentionally invalidate replay of older environment/grader implementation fingerprints; preserve the Git revision to replay old data.

## Scheduling and Recovery

A nonblocking OS advisory lock permits one scheduler per SQLite database. A second CLI/server scheduler fails before recovery can touch live jobs; CLI export and replay can read an active server database. Use `--db` before the subcommand to choose an independent database. Run uvicorn with one worker. The scheduler admits at most 32 active batches, each at most 100 episodes and eight workers. All batches share one eight-episode semaphore. This bounds both waiting tasks and provider calls, not just concurrency within individual jobs. Async concurrency overlaps model I/O; it does not parallelize Python CPU work.

Cancel and shutdown preserve completed episodes and any in-flight partial traces with a cancelled episode status and zero training reward. Unstarted episodes have no fabricated trace. Cancelling a queued job immediately creates a terminal run status. Startup marks abandoned queued/running runs `interrupted`, preserving already stored episodes; it does not silently rerun potentially paid calls. SQL triggers reject episode/event updates and deletes. SHA256 detects accidental/out-of-band content changes, but an administrator with filesystem access can replace the database, triggers and hashes: this is an audit aid, not tamper-proof storage.

The manager owns its submitted provider, including preparation failures and cancellation before workers start. Cooperative closure has a bounded timeout. Failed or timed-out closure changes an otherwise completed batch to failed; cancellation/shutdown preserve cancelled/interrupted status rather than being relabeled as failure; previously persisted episodes remain unchanged and admission is released in `finally`. Cleanup metadata describes the observed result, not proof that an arbitrary extension released external resources. Direct rollout with a caller-supplied provider leaves that provider's lifetime with the caller.

## Providers and Budget Controls

Scripted oracle and intentionally naive baseline policies are free. The registered `local` provider uses structured-JSON actions through Ollama `/api/chat`, an already-installed model and a loopback endpoint (`WORLD_ENGINE_LOCAL_URL`, default `http://127.0.0.1:11434`). It refuses remote addresses and never downloads a model. Requests use `stream=false`, `think=false`, temperature 0, and a 512 output-token bound. The provider validates the installed model catalog and records its digest before a batch. Model requests reuse one pooled HTTP client per batch.

Native evidence has API/console/CLI aliases `local-tools` (v1) and `local-tools-ledger` (v2), plus explicit SDK use. `world_engine.native_config.NativeRunConfig` separately subclasses legacy `RunConfig` with those aliases and literal evaluation-only admission; models.py/ProviderId and shared grader fingerprints are intentionally unchanged. The API accepts the config union, the factory lazily constructs the existing native class, and the console locks evaluation-only for native choices. Availability means installed local catalog entries; tool capability is checked during provider preparation. Stored config retains the alias, while native episode provenance remains provider_id custom with exact class/protocol evidence. At `ef63eda9`, the CLI admits both native aliases with evaluation-only/no-paid settings. Native default concurrency is one, explicitly editable within one through eight; legacy default four remains unchanged. These entrypoint changes do not change native protocol classes/contracts or retroactively execute imported evidence.

`OllamaToolsProvider` uses actual native `tools`; SDK-only `HTTPProvider(config, record_calls=True)` records local structured JSON. Both retain bounded exact application request bytes and raw response-body bytes with paired decision events. The native adapter accepts exactly one tool call and has no JSON fallback or repair retry. Replay checks protocol/source contracts, request reconstruction and action linkage. These records are operator-only/training-ineligible and excluded from SFT, DPO and grouped training candidates even when the task passed, including alternative pools. Direct SDK providers preserve the supplied evaluation_only flag; only registered NativeRunConfig aliases force literal true. They do not supply server-rendered tokens, loss masks or behavior log-probabilities. See [native protocol](native-provider.md) and [recorded JSON](json-provider.md).

Native SDK integration at `d71a05d` adds explicit `ollama-tools-ledger-v2` while leaving default v1 request/contract/configuration rules unchanged. V2 uses the same transport/lifecycle without shared conversation state. Replay regenerates requests from trusted reset observations and verified transitions, never treating recorded context/reconstruction as authority. It pins the ledger/provider/recorder modules, selected protocol/contract and eligibility. The pure builder's 76 tests are separate from this integration. The [later eight-pair access comparison](../artifacts/access-ledger-study/20261010-v1/report.json) at `cc2d4956` has zero business/clean passes for either protocol. No cache/causal speed improvement or untruncated tokenizer-context consumption is established.

OpenAI-compatible and Anthropic HTTP adapters read `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` only from the server environment. Endpoints can be configured with `WORLD_ENGINE_OPENAI_URL` and `WORLD_ENGINE_ANTHROPIC_URL`; endpoint values and authorization headers are never serialized into run configs or traces. Both `WORLD_ENGINE_ALLOW_PAID=1` and per-run `allow_paid=true` are required. Limits cap episodes, decision steps, concurrency, wall-clock time, output tokens, and response bytes. These are bounded calls, not a guaranteed dollar budget: provider pricing and billing behavior remain external. Raw network bodies, exception URLs, validation inputs and credentials are redacted from public errors.

## API Boundary

Default serving binds `127.0.0.1:8000`; the CLI only accepts loopback hosts. Origin/Host validation and `Sec-Fetch-Site` reject hostile browser requests. CORS is not enabled. The Vite server at port 5173 proxies `/api` to the backend. JSON mutations require `Content-Length`, reject chunked uploads, and enforce a 32 KiB body ceiling before reading. Query pagination caps list responses at 100 runs; details intentionally return at most the bounded 100-episode run. The API is not authenticated, multi-tenant, or designed for remote exposure. Local processes are trusted. Reverse-proxy remote publishing is unsupported; add authentication, tenancy, quotas and deployment threat modeling before exposing it.

Routes: `GET /api/health`, `GET /api/environments`, `GET /api/providers`, `GET/POST /api/runs`, `GET /api/runs/{id}`, `POST /api/runs/{id}/cancel`, `GET /api/runs/{id}/export?format=sft|dpo|grpo|traces|atif&quality=passed|all`. List wrappers are `{environments:[...]}`, `{providers:[...]}`, `{runs:[...]}`. All mutation/config/action schemas forbid extra fields. Health exposes the paid global gate, not API keys. Operator details expose check descriptions for diagnosis; training exports exclude grader descriptions/private expected values. ATIF is normalized operator interchange with explicit training ineligibility, not a Harbor trial or training format.

## Dataset Contracts

The scenario ID binds the seeded initial state, public task and environment/grader fingerprints. A separate stable lineage ID binds environment family and seed, independently of implementation, grader or policy revisions. Its deterministic hash assigns 80% train, 10% validation, 10% test; changing code never moves the same family/seed between splits. These are seeded instance splits, not holdouts of entire task templates or world families. All training formats exclude non-train and `evaluation_only=true` episodes structurally. Raw operator traces may include every split. Default quality requires successful, normally completed, invalid-action-free trajectories, and a current-version replay. Reports count excluded heldout/evaluation/quality/replay/unmatched cases; API headers expose record/skipped counts.

SFT uses one example per admitted tool decision, preserving the recorded controller input and assistant action. Built-in training-eligible providers use those exact system/user messages; arbitrary custom-provider internal formatting is not inferred. Native and recorded-JSON evidence modes are never admitted. Oracle-generated examples are synthetic demonstrations, not model-sampled behavior. DPO searches persisted runs for the same scenario, initial prompt, implementation, task and split; it requires a successful chosen trajectory and strictly lower-reward rejected trajectory. DPO completion messages describe a whole tool trajectory and require a trainer adapter; they do not claim compatibility with every text-only DPO trainer. No unmatched preferences are invented.

`grpo` exports `world-engine.grouped-rollouts.v1`: raw comparable candidate trajectories, rewards, policy identities and a learning-signal flag. It explicitly sets `trainable=false` because sampled token IDs, action loss masks, behavior logprobs and frozen checkpoint identity are absent. Mixed-policy candidates are marked `policy_consistent=false`. This is data for a future integration, not a valid on-policy GRPO batch. Running a trainer is not implemented.

## Extension and Isolation

`examples/sdk_world.py` implements a new trusted `Environment`, registers it in `ENVIRONMENTS`, and supplies a custom async provider through `RunManager.submit(config, provider)` and the existing rollout/grade/replay/store path. The manager owns and closes its batch provider; direct `rollout(config, index, provider)` leaves a supplied provider's lifetime with its caller. The registry is trusted Python application code, not an HTTP upload/plugin execution service. CLI environment choices come from `ENVIRONMENTS` when its argument parser is constructed; custom worlds need trusted registration in that process. Custom provider class/source identity is recorded rather than falsely attributing it to the selected built-in config policy.

Reference worlds run in process and expose only allowlisted simulated tool operations: no filesystem, shell, network, or process tools are exposed to a model. Python in-process execution is not a security sandbox. The separate [local Docker SDK](docker-executor.md) supports fresh constrained terminal/file sessions on an approved already-installed exact image. It validates the complete bounded artifact archive, destroys owned resources, then returns detached bytes for trusted grading. It does not turn workflow worlds into sandboxed Python or add a console/API execution provider. Admission is at most two sessions, with explicit resource, network and cleanup limits. There is no Modal/E2B/cloud provisioner.

The separate `scripts/public-benchmark.py` Terminal-Bench runner executes its allowlisted public task; its historical model outcome is not a Docker SDK evaluation. Containers share the Docker Linux kernel and trust the daemon, image and controller. They are not a VM security boundary. Do not execute untrusted Python worlds in the in-process service.
