# Architecture and Trust Boundaries

World Engine is a local single-operator rollout service. It replaces none of the archived prototype files in `prototypes/failure-to-intervention`; that experiment remains a reference for invoice preservation and deterministic verification.

## Ownership

`Environment` owns seeded state, validated tool transitions, atomic rollback on denial, detached observations/snapshots, and trusted final-state grading. `Provider` sees only the current model-visible observation and previous actions/results. `rollout` pins environment, grader, prompt, policy-source and task fingerprints, applies bounded decisions, and records every accepted or rejected transition. `Store` owns SQLite WAL persistence, append-only episode/event records, content hashes and efficient summary queries. `RunManager` owns admission, global concurrency, process ownership, cancellation and shutdown. FastAPI and the CLI use that same manager.

The three reference worlds are `crm-merge`, `refund-ops`, and `incident-control`. Permission rules belong to tool services: agents cannot write approval results, ledger records, incident health, grader labels, or arbitrary state. Each world protects unrelated records and resource conservation. Critical safety violations force reward zero; normally finished but incomplete valid progress can receive partial credit. Timeouts, cancellation, provider errors and step exhaustion receive zero episode reward. Passing requires every trusted check, a normal completed episode, and an explicit finish. A batch can be completed while its episodes fail the task; `termination=max_steps` remains a failed task outcome.

## Determinism and Evidence

Reset uses an isolated `random.Random(seed)`, integer cents, deterministic dates, and service-owned logical audit sequences. Snapshot hashes include the seed, world version, step tick, finished state and all operational state, including rejected-action ticks. Initial data used by graders is deep-copied and never returned to providers as grader state. Observations show operational records and public task policy, not expected final values or check results.

Every episode records the collection Git HEAD and dirty flag when running from a Git checkout, environment/grader module SHA256 fingerprints, task/tool-schema hash, initial prompt/state hashes, Python version, provider class/source fingerprint, model identifier, and local catalog model digest when available. Source fingerprints include a custom world's complete Python module and class, so changes to helper definitions in the custom world module invalidate replay; external dependency revisions still need pinned package/source manifests. `policy_hash` is a configuration/source fingerprint and includes the local model digest; it is not an attestation of a remote model's weights. Hosted model aliases cannot provide reproducible weight identity. Replay requires matching environment/grader implementation fingerprints and verifies every action, result, observation, state hash and final trusted grade. It also recomputes initial/final snapshots, task/prompt/scenario/lineage hashes, split assignment, step/invalid-action counts and controller policy contexts, then checks termination against world completion and reward/pass labels against trusted grading. Incomplete episodes always have zero authoritative reward, regardless of partial grader credit. Replay proves internal consistency and state transitions for recorded actions; it does not authenticate collection provenance, verify reported timing/token usage or external failure causes, or regenerate stochastic model output. For custom providers, recorded `policy_input` is the controller context, not a claim about arbitrary provider-internal request formatting. Storage append/hash checks alone are not semantic validation; every training export applies replay before admitting an episode. Code changes intentionally invalidate replay of older environment/grader implementation fingerprints; preserve the Git revision to replay old data.

## Scheduling and Recovery

A nonblocking OS advisory lock permits one scheduler per SQLite database. A second CLI/server scheduler fails before recovery can touch live jobs; CLI export and replay can read an active server database. Use `--db` before the subcommand to choose an independent database. Run uvicorn with one worker. The scheduler admits at most 32 active batches, each at most 100 episodes and eight workers. All batches share one eight-episode semaphore. This bounds both waiting tasks and provider calls, not just concurrency within individual jobs. Async concurrency overlaps model I/O; it does not parallelize Python CPU work.

Cancel and shutdown preserve completed episodes and any in-flight partial traces with a cancelled episode status and zero training reward. Unstarted episodes have no fabricated trace. Cancelling a queued job immediately creates a terminal run status. Startup marks abandoned queued/running runs `interrupted`, preserving already stored episodes; it does not silently rerun potentially paid calls. SQL triggers reject episode/event updates and deletes. SHA256 detects accidental/out-of-band content changes, but an administrator with filesystem access can replace the database, triggers and hashes: this is an audit aid, not tamper-proof storage.

## Providers and Budget Controls

Scripted oracle and intentionally naive baseline policies are free. Local Ollama uses an already-installed model through a loopback endpoint (`WORLD_ENGINE_LOCAL_URL`, default `http://127.0.0.1:11434`). It refuses remote addresses and never downloads a model. The native `/api/chat` request uses structured JSON, `stream=false`, `think=false`, temperature 0, and a 512 output-token bound. The provider validates the installed model catalog and records its digest before a batch. Model requests reuse one pooled HTTP client per batch and close it on completion/cancellation.

OpenAI-compatible and Anthropic HTTP adapters read `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` only from the server environment. Endpoints can be configured with `WORLD_ENGINE_OPENAI_URL` and `WORLD_ENGINE_ANTHROPIC_URL`; endpoint values and authorization headers are never serialized into run configs or traces. Both `WORLD_ENGINE_ALLOW_PAID=1` and per-run `allow_paid=true` are required. Limits cap episodes, decision steps, concurrency, wall-clock time, output tokens, and response bytes. These are bounded calls, not a guaranteed dollar budget: provider pricing and billing behavior remain external. Raw network bodies, exception URLs, validation inputs and credentials are redacted from public errors.

## API Boundary

Default serving binds `127.0.0.1:8000`; the CLI only accepts loopback hosts. Origin/Host validation and `Sec-Fetch-Site` reject hostile browser requests. CORS is not enabled. The Vite server at port 5173 proxies `/api` to the backend. JSON mutations require `Content-Length`, reject chunked uploads, and enforce a 32 KiB body ceiling before reading. Query pagination caps list responses at 100 runs; details intentionally return at most the bounded 100-episode run. The API is not authenticated, multi-tenant, or designed for remote exposure. Local processes are trusted. Reverse-proxy remote publishing is unsupported; add authentication, tenancy, quotas and deployment threat modeling before exposing it.

Routes: `GET /api/health`, `GET /api/environments`, `GET /api/providers`, `GET/POST /api/runs`, `GET /api/runs/{id}`, `POST /api/runs/{id}/cancel`, `GET /api/runs/{id}/export?format=sft|dpo|grpo|traces&quality=passed|all`. List wrappers are `{environments:[...]}`, `{providers:[...]}`, `{runs:[...]}`. All mutation/config/action schemas forbid extra fields. Health exposes the paid global gate, not API keys. Operator details expose check descriptions for diagnosis; training exports exclude grader descriptions/private expected values.

## Dataset Contracts

The scenario ID binds the seeded initial state, public task and environment/grader fingerprints. A separate stable lineage ID binds environment family and seed, independently of implementation, grader or policy revisions. Its deterministic hash assigns 80% train, 10% validation, 10% test; changing code never moves the same family/seed between splits. These are seeded instance splits, not holdouts of entire task templates or world families. All training formats exclude non-train and `evaluation_only=true` episodes structurally. Raw operator traces may include every split. Default quality requires successful, normally completed, invalid-action-free trajectories, and a current-version replay. Reports count excluded heldout/evaluation/quality/replay/unmatched cases; API headers expose record/skipped counts.

SFT uses one example per tool decision, preserving the exact system/user input sent by the provider and the assistant action. Oracle-generated examples are synthetic demonstrations, not model-sampled behavior. DPO searches persisted runs for the same scenario, initial prompt, implementation, task and split; it requires a successful chosen trajectory and strictly lower-reward rejected trajectory. DPO completion messages describe a whole tool trajectory and require a trainer adapter; they do not claim compatibility with every text-only DPO trainer. No unmatched preferences are invented.

`grpo` exports `world-engine.grouped-rollouts.v1`: raw comparable candidate trajectories, rewards, policy identities and a learning-signal flag. It explicitly sets `trainable=false` because sampled token IDs, action loss masks, behavior logprobs and frozen checkpoint identity are absent. Mixed-policy candidates are marked `policy_consistent=false`. This is data for a future integration, not a valid on-policy GRPO batch. Running a trainer is not implemented.

## Extension and Isolation

`examples/sdk_world.py` implements a new trusted `Environment`, registers it in `ENVIRONMENTS`, and supplies a custom async provider through `RunManager.submit(config, provider)` and the existing rollout/grade/replay/store path. The manager owns and closes its batch provider; direct `rollout(config, index, provider)` leaves a supplied provider's lifetime with its caller. The registry is trusted Python application code, not an HTTP upload/plugin execution service. CLI environment choices use the built-in list; import registration in an SDK process for custom worlds. Custom provider class/source identity is recorded rather than falsely attributing it to the selected built-in config policy.

Reference worlds run in process and expose only allowlisted simulated tool operations: no filesystem, shell, network, or process tools are exposed to a model. Python in-process execution is not a security sandbox. The core rollout SDK has no Docker/Modal/E2B execution adapter. The separate `scripts/public-benchmark.py` Terminal-Bench runner does provide Docker isolation for its allowlisted public task; it is not a generic SDK executor. A safe external runner separates the controller/grader and secrets from a nonroot task process, isolates per-episode writable state, and enforces network/capability/PID/memory/CPU/time/output limits. A container does not provide a VM security boundary. Do not execute untrusted Python worlds in this in-process service.

## Verification

`bash scripts/backend-check.sh` runs lint, focused tests, and the custom-world SDK example. Default CI also builds the frontend and makes no model calls. `uv run python -m world_engine benchmark` creates raw paired local CPU timing trials and Markdown for three worlds, two scripted policies, concurrency 1/4/8, with scheduling, hashing, trusted grading and SQLite writes included. Repeated trials improve timing measurements; pass intervals count distinct scenarios once. `uv run python examples/local_model_benchmark.py` evaluates already-installed qwen3:8b on matched seeds and records actual latency/tokens/digest/actions/replay results. Those runs are evaluation-only. `uv run python examples/generate_dataset.py` creates separate train-split demonstration/preference examples and export manifests.

`examples/schema_cache_comparison.py` runs a controlled same-code CPU comparison by bypassing only the cached-schema memoization wrapper in its standalone process, then enabling it. It asserts identical scenario IDs, fingerprints and outcomes and preserves both raw timing receipts. `examples/io_overlap_benchmark.py` separately adds an explicitly simulated 25ms await per decision to prove bounded concurrent I/O overlap; this is not real model throughput. Cached tool schemas remain private and every public metadata/observation value is detached, so mutating one observation cannot affect another agent's available tools.

The final local-model collector saves `local-model-traces.jsonl` with full synthetic operator episodes labeled `evaluation_only=true`, `training_eligible=false`. Replay them without the ignored SQLite database using `uv run python -m world_engine replay --file examples/benchmark-results/local-model-traces.jsonl`. These operator evidence files include diagnostic grade descriptions and snapshots; training export paths remain separately filtered and do not copy grader descriptions. Collection `git_dirty` describes the entire checkout, while `implementation_dirty` explicitly covers `src/world_engine`, `pyproject.toml` and `uv.lock`; docs/artifact edits do not falsely imply changed runtime implementation, and the overall dirty flag is never hidden.
